## Excluded candidates

This campaign does not add LIEF 0.17.6, LLVM (llvmorg-22.1.8), Remill 6.0.1, RetDec 5.0, LMDB, minizip-ng 4.2.2, .NET hosting, or ILSpy to the C02 workspace path; their staged presence is source-only and is not evidence that they are shipped by this change. RetDec 5.0 is source-only and incomplete for build: it requires a network fetch of the avast LLVM fork plus the remote retdec-support package, violating the repository's fail-closed no-download dependency rule, and its whole-binary lift pipeline offers lower type-recovery quality than the shipped Ghidra 12.1.2 engine and typed_ast_v2 pipeline. Remill 6.0.1 is source-only and requires LLVM CONFIG, XED, glog, and gflags packages, none of which are staged; its machine-code-to-bitcode lifting role is already covered by the shipped Triton, Unicorn x86, Z3, and Ghidra p-code engines. The llvmorg-22.1.8 tree is a 1.93 GB / 169,029-file source-only monorepo with zero linkable consumers: RetDec requires the avast fork's custom old API and Remill 6.0.1 predates the LLVM 22 API. LIEF 0.17.6 is source-only; AiDA's own PE coverage (`pe_image.cpp`, `pe_parser.hpp`) is comprehensive and streaming/bounded, and LIEF would add a second parser stack plus its mbedtls/spdlog closure to the protected binary. LMDB is source-only; SQLite is the declared authoritative store and is deeply integrated (schema v9, WAL, persistent prepared statements), so an LMDB swap is a rewrite with regression risk and no proven bottleneck. minizip-ng 4.2.2 is excluded by policy: the ZIP/container sources use their bounded byte-provider ZIP/ZIP64 implementations with the existing `zlibstatic` target plus zstd and liblzma codecs and do not consume minizip-ng. .NET hosting and ILSpy remain outside the C02 workspace path; the existing managed CLI decompiler provider is unchanged. Existing Unicorn integration is unchanged, and Triton now shares the pinned Capstone 5.0.9 target required by C02.

## Unresolved dependency compatibility blocker

`src/standalone/src/core/analysis/workspace/mips_decoder.hpp` still declares `mips_decoder_profile_t::capstone_version_extra` as `7`, while the required local Capstone 5.0.9 header defines `CS_VERSION_EXTRA` as `9`; `mips_decoder.cpp` enforces equality with a `static_assert`. The production source is outside this package lease, so this exact source-owned compiler blocker remains unresolved.

## Verification boundary

The source paths, version macros, staged source hashes, license-file hashes, and current Git identities above were checked from the local repository. The Capstone and JSON Schema Validator notice artifacts are text-identical to their pinned local license files after newline normalization. The two Ghidra notice artifacts have the same Git blob identities and SHA-256 values as root `LICENSE` and `NOTICE` at pinned commit `c0f584bf229fffba61d36431f3ce30c0c3e4e682`, without fetching or expanding the sparse checkout. The campaign did not configure, build, link, protect, package, launch, or run a harness. Final package contents and notice placement therefore remain intentionally unverified and must be proven by the later packaging campaign.
